### Post-review corrections (the resampling filter, and the populations the numbers describe)

Both gaps below were found after the review, by re-measuring rather than re-reading, and both are reflected in the artifacts above.

- **The identity graph did not resample the way the reference does.** The Context claimed the decode "is already right … matching the model's own `Resize((384, 384))`", but an unqualified ffmpeg `scale` filter resamples with **bicubic** while the reference (`imgutils/metrics/ccip.py`) calls `Image.resize(..., BILINEAR)`. Measured on the same collection, same graph and same normalization: per-image cosine between the two filters is p50 0.9982, p01 0.9935, min 0.9360, and only 638 of 3840 images reach 0.999 — so task 3.2's gate could not have passed as planned, and the requirement's "exactly as the reference prepares it" was already violated in shipped code. The change now adopts the reference's filter (`scale=384:384:flags=bilinear`, task 2.4), the input contract names it (requirement and task 2.2), and the reference filter is also the marginally better feature set (pair best-F1 0.751 against 0.741; 0.580 against 0.541 at the shipped threshold).
- **The numbers described an artificial population.** The calibration protocol replays the decision rule over all images as if every one were unknown, while the pipeline never clusters the images the tag routing already placed. The design and proposal now state both: the proposal and the design's D5 still open with the protocol pair (pair F1 0.480 → 0.580, clustering F1 0.561 → 0.584, which is what the calibration was fitted on) and then give the populations the pipeline governs (unassigned images 0.684 → 0.713, end to end 0.697 → 0.707). No measured value changed — the population each one belongs to is now named.

Measurement method, recorded so the numbers can be re-derived: the collection is copied, run by the CLI so the features come from the pipeline's own cache, and replayed offline with the shipped cosine (a centroid is a mean of unit features, so the comparison is `(centroid · feature) / ‖centroid‖`; a raw dot against a cosine-calibrated threshold shifts the effective threshold by about 1/0.9 and over-fragments), with images mapped to their produced folder by content hash because the organized tree is flat per character and file names repeat across characters.
