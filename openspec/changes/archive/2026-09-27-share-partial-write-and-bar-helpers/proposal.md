## Why

Three mechanics are written more than once, and the copies have already drifted:

- **Finalizing a partial output.** `compressImage` (`src/picture/picture_compress.cpp:84-95`) and `finalizeConvertedOutput` (`src/picture/picture_video_webp.cpp:62-78`) both do "remove the target, `fs::rename` the partial onto it, warn, return `false`" against the same `partialTempPath` rule (`src/picture/picture_compress.h:25`, `src/picture/picture_compress.cpp:38-41`). They differ only in the warning text and in the `fs::exists` guard the conversion adds (`picture_video_webp.cpp:64`) — a guard the compression path already has earlier, with its own warning (`picture_compress.cpp:75-82`).
- **Staging a serialized file before renaming it into place.** Three persistence paths write a temp file and rename it: `jobstate::detail::flushSnapshot` (`src/core/job_state.cpp:481-497`), `organize::AnalysisCache::saveLocked` (`src/organize/cache.cpp:179-187`) and `probecache::save` (`src/video/probe_cache.cpp:175-203`). They agree on the body — open the temp, write, flush, close — and disagree on everything around it: throttling (2 s force-able, `job_state.cpp:27,477` / 64-put batch, `organize/cache.h:30` / none), error channel (`eh::Result` with two distinct messages, `job_state.cpp:483-493` / silent, `cache.cpp:182,185` / `LOG_WARN`, `probe_cache.cpp:180,207`), directory creation (`cache.cpp:177` alone), temp suffix (`makeTempStatePath`, `job_state.cpp:58-60` / `".tmp"` appended to the file string, `cache.cpp:179` / pid suffix, `probe_cache.cpp:175-176`), and the rename itself (`job_state.cpp:498-502` removes the target and retries; the other two rename once). The drift is visible inside the shared body: both the job-state and the organize copies check the write (`if (!output)`, `job_state.cpp:491`; `if (!out)`, `cache.cpp:185`), the probe-cache copy does not (`probe_cache.cpp:177-203`).
- **Building the per-slot progress bars.** `initSlotBars` (`src/video/encode_probe.cpp:536-545`) and `EncodingProgressState::makeSlotBars` (`src/video/video_batch_execution.h:115-129`) are the same loop modulo the label (`"Probing"` vs `"Encoding"`) and where the `progress::showsSlotBars` gate sits (at the caller, `encode_probe.cpp:560`, vs inside the helper, `video_batch_execution.h:121`). The idle text is a third copy: `EncodingExecutionContext::barIdle` (`video_batch_execution.h:219-225`) formats the same `"Encoding: [idle-{}]"` postfix (`:224`) when a worker goes idle, so the shared idle-text rule would serve the two builders and `barIdle`. The extraction was implemented, measured at 38 lines added in `progress.{h,cpp}` against 27 net removed at the two call sites (net +11) and reverted — design D3 records it; the three copies stay.

Why now: the media-item/stage unification just landed (`unify-media-item-and-stages`, `migrate-video-to-media-items`), so the picture, organize and video flows now sit on one seam; the copies of these three mechanics are what a per-flow change would still have to be made in twice or three times, and one of them has already been fixed in only two of its three copies.

## What Changes

- **One partial-output finalize.** `finalizePartialOutput(fs::path const& outputPath) -> std::error_code` added beside `partialTempPath` in `src/picture/picture_compress.h`; it removes the target and renames the partial onto it, returning the rename's error code (cleared on success). Both sites adopt it and keep their own warning text, their own `fs::exists` guard and their own `false`/`true` return convention. The helper owns no policy: it does not check existence, does not log, and does not decide what a failure means.
- **One staging write.** `fileio::writeStagingFile(stagingPath, content, mode) -> fileio::StagingStatus` added as a header-only helper in `src/core/file_write.h`; it opens the caller's temp path, writes, flushes, closes, and reports `Written` / `OpenFailed` / `WriteFailed`. Every caller keeps its own temp name (the suffixes are load-bearing, see design `D2`), its own throttle, its own error channel and wording, its own directory creation, and its own rename — including job-state's remove-and-retry (`job_state.cpp:498-502`), which is not shared.
- **Not extracted: the slot-bar builder.** `progress::makeSlotBars` / `progress::slotBarIdleText` were implemented and measured at 38 lines added in `progress.{h,cpp}` against 27 net removed at the two call sites (net +11): `progress.{h,cpp}` gained 38 lines while the two call sites shed 27 net, and what is actually shared is a one-line `[idle-N]` format plus a one-line `showsSlotBars` gate. Design D3 had pre-authorised the cut, so the extraction was reverted — the two builders and `barIdle`'s postfix are back to their pre-change bodies and `src/core/progress.{h,cpp}` is unchanged by this change. The duplication and the three `[idle-...]` writers stay; design D3 records the measurement.
- **Not merged: the extension lists.** `organize::kImageExtensions` (`src/organize/scan.h:20-29`, 8 entries including uppercase), `readAllPics`'s `pictureTypes` (`src/picture/picture_process.cpp:802-811`, 7 entries, no `.webp`, with `.bmp`/`.tiff`/`.gif`/`.heic`) and `kVideoTypes` (`src/video/video_info.cpp:31-38`, 6 lowercase entries) disagree, and `pack::kStoredMediaExtensions` (`src/pack/pack_types.h:22-53`) answers a different question (STORE vs deflate, already case-insensitive through `shouldStoreEntry`, `:55-61`). Unifying them changes which files each command sees; this change records the disagreement in `docs/backlog.md` and fixes nothing.
- **Tests: no existing test edited; one new case for the new helper.** The existing suites are the correctness evidence for the adopted sites — `[picture]`/`[picture-compress]` (`tests/picture/picture_compress_tests.cpp`), `[picture-process]`/`[video-webp]` (`tests/picture/picture_video_webp_tests.cpp`), `[job-state]` (`tests/job_state_tests.cpp`, including "job state mark operations report persistence failures", `:823`), `[organize]` (`tests/organize/stage_tests.cpp`, the `AnalysisCache` cases at `:61-190`) and `[probe-cache]` (`tests/video/probe_cache_tests.cpp`); `[encode-probe]`, `[video-batch-execution]` and `[progress]` stay green over the reverted bar code. A new case in `tests/file_write_tests.cpp` pins `fileio::writeStagingFile`'s own contract — a writable path reports `Written` with the content landed, an unopenable one reports `OpenFailed`; `WriteFailed` has no portable trigger and is recorded there as uncovered. `finalizePartialOutput` still has no direct case: its error branch is exercised through its callers and its regression is the two warning strings, unchanged from the pre-extraction code. The acceptance bar is that no existing test file is edited and the console output does not move.

No output change in any command: the same files are written, the same partials are renamed, the same bars are created with the same text. The one ordering change is internal: because `writeStagingFile` takes the content as an argument, `flushSnapshot` and `probecache::save` serialize before attempting the open where they open first today (design D2); every failure path prints the same line.
