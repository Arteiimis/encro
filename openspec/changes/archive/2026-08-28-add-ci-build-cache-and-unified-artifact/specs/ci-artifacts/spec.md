## Purpose

Defines the behavior contract for what the CI pipeline publishes per workflow run: one unified `ci-run-*` artifact that consolidates every per-mode test report and the coverage report, so post-run investigation (success or failure) is a single download.

## ADDED Requirements

### Requirement: Unified per-run artifact

The CI pipeline SHALL publish one artifact per workflow run whose name is `ci-run-<timestamp>-r<run-id>`, where `<timestamp>` is the UTC time the collection job ran (format `YYYYMMDDTHHMMSSZ`) and `<run-id>` is the unique GitHub Actions run identifier. The artifact SHALL be published for every run outcome, including runs where all jobs succeed.

The unified artifact SHALL contain, as separate subdirectories preserving their origin, the per-mode test report artifacts (`test-reports-<mode>` for each matrix mode) and the coverage report artifact (`coverage-report`). Downloaded content SHALL be a single zip archive.

#### Scenario: Successful run publishes the unified artifact

- **WHEN** a workflow run completes with all jobs passing
- **THEN** a single `ci-run-<timestamp>-r<run-id>` artifact exists for that run
- **AND** downloading it yields one zip containing the per-mode test reports and the coverage report in separate subdirectories

#### Scenario: Failed run still publishes the unified artifact

- **WHEN** a workflow run completes with any job failing
- **THEN** the unified `ci-run-<timestamp>-r<run-id>` artifact still exists for that run
- **AND** it contains the reports generated by the jobs that ran

#### Scenario: Artifact names are unique per run

- **WHEN** two workflow runs are collected within the same second
- **THEN** their unified artifacts have different names because the run-id suffix differs

### Requirement: Per-mode test report content

Each per-mode `test-reports-<mode>` artifact SHALL contain the JUnit report, the unit-test console log, the encro runtime logs, and the preserved e2e failure scratch directories. It SHALL be (re)published for every run outcome (not only failures), and missing scratch directories (e.g. all e2e tests passed) SHALL NOT fail the upload.

#### Scenario: Failing e2e leaves its scratch dirs in the artifact

- **WHEN** an e2e test fails and its scratch directory is preserved
- **THEN** that scratch directory appears inside the `test-reports-<mode>` artifact for the run

#### Scenario: Passing run uploads test reports without scratch dirs

- **WHEN** all e2e tests pass and no scratch directory is preserved
- **THEN** the `test-reports-<mode>` artifact is still published containing reports and logs
- **AND** the absence of scratch directories does not fail the upload
