# Spec Delta

## Purpose

Carries the tool to Windows users through a Scoop bucket: a manifest whose version and download URL follow each release, a shim the bucket generates so the command lands on the user's PATH, and an update step that never endangers the release that triggered it.

## ADDED Requirements

### Requirement: The bucket installs the released Windows artifact

A Scoop bucket SHALL provide a manifest that installs the tool from the Windows artifact of a published release. Installing it SHALL put an `encro` command on the user's PATH without the user creating or editing any file.

#### Scenario: Installing from the bucket yields a working command

- **WHEN** a user adds the bucket and installs the package
- **THEN** an `encro` command is available on the PATH
- **AND** running it reports the version the manifest names

#### Scenario: The shim is generated by Scoop, not shipped

- **WHEN** the package is installed
- **THEN** the command resolves through a shim Scoop created from the manifest
- **AND** no shim needs to be written by hand beforehand

### Requirement: The manifest tracks one release version at a time

The manifest SHALL state exactly one version, in the same three-part numeric form the release's tag carries without its `v` prefix, and SHALL point at the artifact of that same release. The manifest's version and the asset it downloads SHALL never name different releases.

#### Scenario: The manifest version matches the tag

- **WHEN** the manifest describes release `2.0.1`
- **THEN** its version field reads `2.0.1` with no `v` prefix
- **AND** its download URL contains `2.0.1`

#### Scenario: A manifest update moves both fields together

- **WHEN** a new release changes the manifest
- **THEN** the version field and the download URL both name the new release

### Requirement: Installing verifies the downloaded artifact

The manifest SHALL carry a checksum for the artifact it downloads, and an installation whose downloaded file does not match that checksum SHALL fail rather than install the file.

#### Scenario: A mismatched download is refused

- **WHEN** the downloaded artifact's hash differs from the manifest's checksum
- **THEN** the installation fails
- **AND** the tool is not installed from that file

### Requirement: A release updates the bucket without risking itself

Publishing a release SHALL update the bucket's manifest to that release. If the update fails, the release SHALL still stand: both artifacts and the release text SHALL remain published, and the failure SHALL be reported so the update can be repeated by hand.

#### Scenario: A failed bucket update leaves the release intact

- **WHEN** the bucket update fails while a release is being published
- **THEN** the release and both its artifacts are still published
- **AND** the run reports that the bucket update failed

#### Scenario: A successful update leaves the bucket on the new version

- **WHEN** the bucket update succeeds
- **THEN** the bucket's manifest names the newly published version
- **AND** a user installing afterwards receives that version

#### Scenario: An unpublished release never reaches the bucket

- **WHEN** a release is aborted because a gate failed
- **THEN** the bucket's manifest is unchanged

### Requirement: The bucket states the external prerequisite

The manifest SHALL tell the user, at install time, that the media programs the tool invokes are required and are not installed by this package.

#### Scenario: The prerequisite is visible when it matters

- **WHEN** the package is installed
- **THEN** the user is told which external programs must already be present
- **AND** the package does not silently install or bundle them

### Requirement: A previously hand-installed command is replaced, not duplicated

Where the tool's command was previously provided by a hand-written shim pointing at a local build, installing the package SHALL leave exactly one `encro` command on the PATH, resolving to the installed release.

#### Scenario: One command after migration

- **WHEN** the package is installed on a machine that previously carried the hand-written shim
- **THEN** exactly one `encro` command is on the PATH
- **AND** running it reports the installed release's version rather than executing a binary in a local build directory

#### Scenario: The previously installed command keeps working across an upgrade

- **WHEN** a newer version replaces an already installed one
- **THEN** the same single `encro` command now reports the newer version
- **AND** no second command appears beside it
