## Context

Two full `clang-include-cleaner` scans were run on branch 3b9c859: Windows (clang-cl 23.1, MSVC STL, release compile_commands.json) and Linux (WSL Ubuntu 24.04, clang 19.1.7, libstdc++, release). Results: 111 vs 118 unused includes, 100-item intersection, 29 platform-divergent. The 100-item intersection list is at `build/include_cleaner_intersection.txt` (format `TU|header`, TU paths normalized to `/`). The WSL copy at `~/encro` is synced to 3b9c859 and already built (release, compile_commands.json current), so Linux re-verification is cheap.

## Goals / Non-Goals

**Goals:**
- Delete exactly the 100 intersection includes; annotate exactly the 29 divergent ones.
- Both-platform `xmake include-cleaner` scans report zero unused includes after the change.
- Builds and full test suites stay green on both platforms.

**Non-Goals:**
- Adding `include-cleaner --check` to CI (needs its own decision; the annotation work here makes it possible).
- Fixing the analysis tooling itself (clang-include-cleaner version skew between LLVM 23 and 19 is out of scope).
- Any include *additions* or code changes — include lines only.

## Decisions

1. **Intersection strategy** — delete only includes both scans flag. Alternatives rejected: delete the Windows-only 111 (breaks Linux build via transitive dependencies); delete the Linux-only 118 (breaks Windows). The intersection is the set both compilers agree is unused, so both platforms' builds remain the verification gate.
2. **Annotation mechanism: `// IWYU pragma: keep`** — verified experimentally: adding it to `stop_signal.cpp`'s `<array>` dropped that file's findings from 2 to 0 on Windows. Alternatives rejected: `// NOLINT` comments (clang-tidy's `misc-include-cleaner` is not enabled in `.clang-tidy`; NOLINT is ignored by the standalone `clang-include-cleaner` binary the plugin wraps). Comment text: `// IWYU pragma: keep -- <one-line reason>` where the reason names the platform quirk (e.g. "needed with MSVC STL; Linux libstdc++ pulls it transitively").
3. **Re-scan, don't trust the saved list** — the saved intersection was computed on branch 3b9c859; apply-time protocol re-runs both scans and treats the *fresh* intersection as authoritative (alive-at-delete items are kept and reported, mirroring reduce-over-engineering's deletion protocol). This absorbs any drift from the review-fix commit.
4. **Batch granularity: one commit** — include-line deletions and annotations are mechanical and low-risk; splitting by module adds no rollback value (`git revert` of one commit rolls back cleanly).
5. **Verification order: Windows first, then Linux** — Windows `xmake test-report` + scan, then WSL build + scan; both scans must report 0. The WSL build is incremental after the include edits (compile_commands regenerated by `xmake build`).

## Risks / Trade-offs

- [Deleting an include that a platform scan misses due to scan staleness] → apply-time protocol re-runs both scans fresh; intersection is recomputed, not reused.
- [`IWYU pragma: keep` on a header the tool would legitimately flag on one platform] → that is the intent: the 29 items are kept *because* one platform needs them; the comment records why so the annotation survives future audits.
- [WSL scan uses clang 19 vs Windows clang 23 — version skew may shift findings] → intersection strategy is conservative by construction: only findings present under both toolchains are deleted; divergent findings are annotated, never deleted.
- [Comment churn in `#if defined(_WIN32)` blocks] → annotations only touch include lines; pre-commit clang-format handles layout.

## Migration Plan

1. Re-run both scans on the apply branch; compute fresh intersection (expected ≈100).
2. Delete intersection includes via per-file edits; annotate the 29 divergent items with `IWYU pragma: keep`.
3. Windows: `xmake build` + `xmake test-report` + `xmake include-cleaner` (expect 0).
4. WSL: sync branch, `xmake build` + `xmake include-cleaner` (expect 0).
5. Single conventional commit (`refactor:`), ticking tasks.md in the same commit.
6. Rollback: `git revert` of the one commit; both platforms' builds were green before, so revert restores them.
