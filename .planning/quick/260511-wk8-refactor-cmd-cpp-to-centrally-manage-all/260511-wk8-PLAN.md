**Step D — Data-driven flag registration loop:**

Iterate over a `std::array` of group descriptors, each pairing a constexpr array reference, a group pointer (or `app`), and a group description:

```cpp
struct FlagGroup {
  std::span<CmdFlagDef const> defs;
  CLI::App*                   target;
};

auto const groups = std::array<FlagGroup, 5>{
  FlagGroup{GeneralFlags,    &app},        // help, version → app; rest also go here? NO — see below
  // ...
};
```

**CRITICAL — help/version go on `app`, NOT on `general` group.** The GeneralFlags array contains 7 entries: indices 0-1 (help, version) must be registered on `app` directly; indices 2-6 (verbose, verbose-echo, full-progress, color, yes) on the `general` group. Handle this by splitting GeneralFlags into two iteration passes, or by using an if-check during iteration.

Recommended approach — iterate GeneralFlags entries 0-1 on `app`, entries 2-6 on `general`:

```cpp
// Help and version — registered on app (not in any group)
for (auto const& def : std::span{GeneralFlags}.subspan(0, 2)) {
  auto* opt = [&]() -> CLI::Option* {
    switch (def.kind) {
      case CmdFlagKind::Bool:
        return app.add_flag(def.name, def.description);
      default:
        return nullptr; // help/version are always Bool
    }
  }();
  if (opt) optRegistry[def.name] = opt;
}

// Remaining GeneralFlags (5 entries) — registered on general group
for (auto const& def : std::span{GeneralFlags}.subspan(2)) {
  // ... register on general
}
```

**Registration switch logic (per flag):**

For each `CmdFlagDef`, derive `expectedMin` from `defaultValue` (empty → 1, non-empty → 0), then:

| kind | expectedMax | defaultValue | CLI11 call |
|------|-------------|-------------|------------|
| Bool | 0 | (ignored) | `target->add_flag(def.name, def.description)` |
| String | 1 | "" | `target->add_option(def.name, def.description)->expected(1)` |
| String | 1 | non-empty | `target->add_option(def.name, def.description)->expected(0,1)->default_str(def.defaultValue)` |
| Int | 1 | "" | `target->add_option(def.name, def.description)->expected(1)` |
| Int | 1 | non-empty | `target->add_option(def.name, def.description)->expected(0,1)->default_str(def.defaultValue)` |
| SizeT | 1 | "" | `target->add_option(def.name, def.description)->expected(1)` |
| SizeT | 1 | non-empty | `target->add_option(def.name, def.description)->expected(0,1)->default_str(def.defaultValue)` |
| VecString | N | "" | `target->add_option(def.name, def.description)->expected(0, def.expectedMax)` |

Note: `expected(0, 1)` is used when a default exists so CLI11 allows omitting the option entirely (count=0 uses default). `expected(1)` is used when no default — option takes exactly 1 value if present, count=0 if absent.

After registering, store `optRegistry[def.name] = opt;`.
