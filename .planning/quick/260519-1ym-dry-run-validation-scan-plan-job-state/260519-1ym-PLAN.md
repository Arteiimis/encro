### Design constraints (per dry-run-design-decisions.md)

1. **Three-layer progressive output** (decision #1): Validation -> Scan -> Plan. Format:
```
── Dry-Run: Validation ──

── Dry-Run: Scan ──

── Dry-Run: Plan ──
```
Use `terminal::println(Heading, "...")` for section headers.

2. **Each layer failure skips subsequent layers** (decision #2): Each layer collects failures. If any `[FAIL]` in Validation, return error immediately. If any `[FAIL]` in Scan, return error before Plan. `[WARN]` allows continuation.

3. **Read-only job state** (decision #3): NEVER call `Store::initialize()`. Instead, check `fs::exists(stateFilePath)`. If exists, use `jobstate::detail::loadSnapshot(stateFilePath)` from `src/core/job_state_detail.h` to get a `Snapshot`. Read `snapshot_.tasks` to count completed/pending. Do NOT call any Store methods that write.

4. **Output dir check only** (decision #4): Check parent of output directory exists and is writable. Use `fs::status(parentPath).permissions() & fs::perms::owner_write`. Do NOT call `fs::create_directories()`.

5. **Full recursive scan** (decision #5): Use `media::scanByExtensions()` with appropriate extension lists. Video: `{".mp4"sv, ".mkv"sv, ".avi"sv, ".mov"sv, ".flv"sv, ".wmv"sv}`. Picture: `{".jpg"sv, ".jpeg"sv, ".png"sv, ".webp"sv, ".bmp"sv, ".tiff"sv, ".gif"sv, ".heic"sv}`.

### Implementation structure

```cpp
// src/app/dry_run.cpp
#include the necessary headers (pipeline.h, terminal.h, media_scanner.h, job_state_detail.h, error_handle.h)
// plus <filesystem>, <span>, <array>, etc.

namespace pipeline {
namespace {

// Helper: build extension list from processType
auto extensionsForType(std::string_view processType) -> std::vector<std::string_view>;

// Validation layer returns failure count
struct ValidationResult { std::size_t failures = 0; };
auto runValidation(appctx::AppContext const& ctx) -> ValidationResult;

// Scan layer returns file info + failure flag
struct ScanResult { std::size_t fileCount = 0; std::uintmax_t totalSize = 0; bool failed = false; };
auto runScan(appctx::AppContext const& ctx) -> ScanResult;

// Plan layer returns failure flag
auto runPlan(appctx::AppContext const& ctx, ScanResult const& scan) -> bool;

}  // namespace

auto runDryRun(appctx::AppContext const& ctx) -> eh::Result<int> {
  // Layer 1: Validation
  auto validation = runValidation(ctx);
  if (validation.failures > 0) return eh::makeError("Validation failed with {} check(s).", validation.failures);

  // Layer 2: Scan
  auto scan = runScan(ctx);
  if (scan.failed) return eh::makeError("Scan failed.");

  // Layer 3: Plan
  auto planFailed = runPlan(ctx, scan);
  if (planFailed) return eh::makeError("Plan generation failed.");

  return 0;
}

}  // namespace pipeline
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI args -> AppConfig | Untrusted user input parsed by CLI11, validated in config_builder |
| filesystem reads | File paths from user input, existence/permissions checked before use |
| job state file | Read via detail::loadSnapshot, never modified by dry-run |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-dry-01 | Spoofing | dry-run output | accept | Terminal text output is informational only — no execution side effects. Spoofing dry-run output has no security impact. |
| T-dry-02 | Tampering | job state file read | mitigate | Read-only access via detail::loadSnapshot; no Store::initialize() call means no directory creation, no file modification. fs::exists guard prevents crash on missing files. |
| T-dry-03 | Information Disclosure | file scan | accept | File count/size/names are already visible to the user via filesystem. No sensitive data exposure. |
| T-dry-04 | Denial of Service | recursive scan | accept | Recursive scan could be slow on massive directories, but this is the desired behavior (full scan, not estimate). No amplification — same cost as normal execution's scan phase. |
| T-dry-05 | Elevation of Privilege | output dir check | accept | fs::status().permissions() check is read-only. No directory creation, no file write. |
</threat_model>
