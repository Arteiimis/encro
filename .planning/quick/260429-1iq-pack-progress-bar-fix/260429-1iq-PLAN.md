# Quick Task 260429-1iq: 打包进度条显示错误修复 - Plan

**Created:** 2026-04-28
**Status:** Ready for execution

## Task Description

打包时进度条显示的正在打包指示错误，一直在跳变，包括总待打包数也在跳变。
修复为累计进度显示：`Packing: archive <已完成归档数>/<总归档数> [file <已完成文件总数>/<文件总数>]`

## Root Cause

`src/pack/pack_service.cpp:packGroups()` 第223-269行，紧凑模式下：
1. 多个归档通过 `taskexec::runTasks` 并行执行
2. 进度回调 `[&](fileIndex, fileCount)` 每次更新单条进度条时，使用**各自归档**的 `index+1 / archiveCount` 和 `fileIndex / fileCount`
3. 不同归档的 index 和 fileCount 不同，回调交替触发导致显示值跳变

另外，初始进度条文本（第208行）使用 `plan.groups.front().size()` 作为总文件数，而实际总文件数为 `compactTotalFiles`，这也是一个错误。

## Tasks

### Task 1: 修复 compact 模式进度条为累计计数

**Files:** `src/pack/pack_service.cpp`

**Action:**
1. 在第203行后新增 `std::atomic<std::size_t> completedArchiveCount{0};`
2. 修改第206-214行初始状态：文件总数改用 `compactTotalFiles`，归档数从 `0/archiveCount` 开始
3. 修改第249-254行回调中的 `formatCompactPackingStatus` 调用：两个参数改为累计值
   - archive 部分：`completedArchiveCount.load() / archiveCount`（已完成的归档数）
   - file 部分：`completedFileCount / compactTotalFiles`（已完成的文件总数）
4. 在第283行之后（`zippedFiles[index] = zipPath`）递增 `completedArchiveCount` 并更新进度条文本

**Verify:**
- 运行现有测试：`tests/pack_service_tests.cpp` 中的 compact progress 测试需要随新格式更新

**Done:** Progress bar shows cumulative `completedArchiveCount / archiveCount [completedFileCount / compactTotalFiles]` without jumping.
