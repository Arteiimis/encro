## What Changed

### File: `src/pack/pack_service.cpp`

**Before:** `packGroups()` was a single ~184-line monolithic function (lines 198-381) that handled both compact and non-compact modes with deeply nested conditionals.

**After:**
- **`CompactProgressState` struct** (anonymous namespace, 70 lines): Bundles all compact-mode progress state (`ctx`, `barIndex`, `completedFileCount`, `completedArchiveCount`, `mutex`, `finalizingCount`, `spinnerStop`, `spinnerThread`) with 4 member methods:
  - `initBar()` — creates progress bar, sets initial postfix and callbacks
  - `startSpinner()` — launches `std::jthread` spinner for "Finalizing" animation
  - `tryUpdateStatus()` — unified bar-setter gated on `finalizingCount == 0`
  - `finish()` — stops spinner, sets success tone and "Packed" status

- **`packGroupsCompact()`** (~85 lines): Orchestrator for compact mode using `CompactProgressState`; the file callback lambda now calls `state.tryUpdateStatus()` instead of inline bar-setter logic; the archive completion hook also uses `state.tryUpdateStatus()` for unified behavior.

- **`packGroupsFull()`** (~55 lines): Clean non-compact implementation with no compact conditionals; simplified task lambda uses standard `packFilesToZip(entries, zipPath, taskCtx.progress, label)`.

- **`packGroups()`** (4 lines): Dispatcher — `if (plan.compact) { return packGroupsCompact(plan); } return packGroupsFull(plan);`

### Behavioral Preservation

Every detail from the original code is preserved exactly:
- Same format strings (`formatCompactPackingStatus`, `formatCompactPackedStatus`)
- Same `memory_order` values (`acquire`/`release`)
- Same guard conditions (`finalizingCount == 0`, `barIndex.has_value()`)
- Same callback invocation order (`onCompactProgress` before `onCompactStatusText`)
- Same `setProgress` called unconditionally (outside `tryUpdateStatus` gate)
- Same `scoped_lock{mutex}` pattern for non-atomic field access
