<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Log directory filesystem | Cleanup deletes files matching encro_*.log pattern; if directory is symlinked, unintended files could be deleted |
| Process environment | Log directory derived from LOCALAPPDATA, APPDATA, HOME, TEMP env vars; malicious env manipulation could redirect log output |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | Log file path (symlink attack) | accept | Log dir is user-scoped (%LOCALAPPDATA%); attacker with filesystem access to user's AppData can already tamper with any file. No elevation from log manipulation. |
| T-02-02 | Information Disclosure | Log file path in terminal output | accept | Path display is intentional for user debugging (Hint/Warning level). No secrets in path — it is derived from well-known env vars. |
| T-02-03 | Denial of Service | Retention cleanup deletes too many files | mitigate | Cleanup only matches encro_*.log and encro_*.log.* patterns. Never traverses outside the log directory. Max-delete bounded by filesystem entries in one directory. |
| T-02-04 | Denial of Service | Fallback to temp directory fills disk | accept | temp dir already subject to system cleanup policies. No worse than existing behavior. User is warned via terminal. |
| T-02-SC | Tampering | xmake package installs (no new deps) | accept | Phase 2 adds zero new packages. All functionality uses spdlog (existing dep), C++ standard library, and OS APIs already linked. |
</threat_model>
