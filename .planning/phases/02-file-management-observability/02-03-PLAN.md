    Step B — Add new function `tryWriteDirectToLogFile` in the anonymous namespace, before `tryWriteToLogger` (around line 28):
    ```
    auto tryWriteDirectToLogFile(std::string const& message) -> bool {
        try {
            auto const logPath = logging::currentLogFilePath();
            if (!logPath.has_value()) { return false; }
            auto ofs = std::ofstream(logPath.value(), std::ios::app);
            if (!ofs) { return false; }
            auto const now = std::chrono::system_clock::now();
            // Manual format matching spdlog kLogPattern: [timestamp] [critical] [infra.crash] message
            auto const formatted = std::format(
                "[{:%Y-%m-%dT%H:%M:%S}] [critical] [infra.crash] {}\n",
                now, message
            );
            ofs.write(formatted.data(), static_cast<std::streamsize>(formatted.size()));
            return true;
        } catch (...) {
            return false;
        }
    }
    ```

    Note: `std::format` with `std::chrono::system_clock::time_point` uses chrono format specifiers. On clang-cl with libc++, the `{:%Y-%m-%dT%H:%M:%S}` format for `time_point` may require `std::chrono::floor<std::chrono::seconds>(now)` for second precision, or conversion via `system_clock::to_time_t()` + `std::localtime()` + `std::strftime()`. The executor should use the approach that compiles cleanly on the project's toolchain. The fallback-safe approach: convert to `time_t` via `std::chrono::system_clock::to_time_t(now)`, then use `std::localtime()` and `std::strftime()` with buffer `"%Y-%m-%dT%H:%M:%S"` — this is universally supported.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Log file path from currentLogFilePath() | Crash handler reads path from module-level variable set during setup(). Trust boundary: path could be stale if setup.cpp's module variable is corrupted. Mitigation: module variable is only set once during setup(), never modified mid-run. |
| Direct file write via std::ofstream | Bypasses all spdlog safety mechanisms (mutex, queue ordering). Multiple crash handler invocations could interleave writes. Mitigation: crash handler fires at most once per process (after which std::_Exit is called). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-08 | Tampering | Direct file append bypasses spdlog | accept | Only used during crash (terminal state). No concurrent spdlog writes occur after crash handler fires since std::_Exit terminates the process. No interleaving risk. |
| T-02-09 | Denial of Service | Crash handler file write fails | mitigate | 3-tier fallback ensures message reaches SOME output. Direct file -> spdlog -> stderr. Every path returns false cleanly on failure, allowing next tier to try. |
| T-02-10 | Information Disclosure | Crash message includes file paths | accept | By design — crash diagnostics include file paths for debugging. User-scoped log directory prevents other users from reading. |
| T-02-SC | Tampering | No new packages | accept | Only C++ standard library (chrono, fstream) and existing project headers used. |
</threat_model>
