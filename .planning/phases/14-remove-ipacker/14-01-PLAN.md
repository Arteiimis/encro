<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PackService→Packer (value member) | PackService calls Packer methods directly on packer_ member |
| Test→PackService+TempDir | Integration tests use TempDir for isolated file I/O |
| Consumer→pack::execute() | Consumers call execute() free function — internal Packer/PackService hidden |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Tampering | `pack.cpp` construction sites | accept | Construction sites are internal; consumers only use pack::execute() which manages lifecycle |
| T-14-02 | Tampering | Test TempDir files | accept | Tests use isolated TempDir scopes; zero production data exposure |
| T-14-03 | Information Disclosure | Packer value member | accept | Packer holds no secrets — only grouping/zlib I/O logic; zero sensitive state |
| T-14-04 | Denial of Service | Deleted IPacker virtual dispatch | mitigate | Removing virtual dispatch eliminates vtable indirection — slightly faster, no new DoS surface |
| T-14-05 | Elevation of Privilege | PackService default constructor | accept | No privilege change — Packer() is default-constructible; same capability as before |

## Security Impact Assessment

**Net security posture: IMPROVED.**
- Removed virtual dispatch eliminates one class of vtable corruption attacks (though low risk given local-only execution).
- Value semantics eliminate heap allocation lifetime bugs (use-after-free, double-free via unique_ptr mismanagement).
- No new attack surface introduced — same zip I/O logic, same file system access patterns.
</threat_model>
